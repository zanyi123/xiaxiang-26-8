# 素材精准匹配方案

> **核心理念**：将网站所有需要填充素材的“位置”可视化编号，后台提供一个“填字游戏”式的匹配界面，实现素材与网站位置的精准映射。

---

## 一、网站素材空位（Slot）编号体系

### 1.1 编号规则

- **格式**：`[类型缩写]-[模块序号]-[位置序号]`
- **类型缩写**：
  - `IMG` (Image) - 图片
  - `VID` (Video) - 视频
  - `MDL` (Model) - 3D模型
  - `AUD` (Audio) - 音频

## 二、网站前端 UI 标识设计

在网站前端页面上，对于需要填充但尚未填充真实素材的位置，显示该 Slot 编号作为占位符或角标。

### 2.1 设计稿示例

以 `index.html` 的“云游侨乡”地图区为例：

```html
<!-- 原来的占位 -->
<div class="building-card">
    <div class="card-image">
        <!-- 显示编号和类型 -->
        <div class="slot-placeholder">
            <span class="slot-badge">IMG-02-01</span>
            <span class="slot-type">🖼️</span>
            <span class="slot-status">待填充</span>
        </div>
        <!-- 填充后替换为真实图片 -->
        <!-- <img src="images/diaolou.jpg" alt="碉楼群"> -->
    </div>
    <div class="card-title">碉楼群</div>
</div>
```

### 2.2 视觉表现

- **有素材时**：显示真实图片/视频/3D模型
- **无素材时**：显示半透明灰色占位符，中央显示 Slot 编号，带小图标说明素材类型（🖼️图片、🎬视频、🧊模型、🎵音频）
- **悬停提示**：鼠标悬停显示描述信息

### 3.2 交互流程

1. **加载**：页面加载时，自动从 `application.yml` 解析出所有 Slot，同时列出 COS 桶内所有已有素材。
2. **匹配**：用户在右列的素材卡片上，从下拉菜单选择要匹配的 Slot 编号。
3. **预览**：中列实时显示该 Slot 状态变为“待确认”，高亮黄色。
4. **确认导入**：
   - 点击“确认导入”后，系统把素材的 COS Key 写入 `application.yml` 的对应字段。
   - 状态从“待确认”变为“已填充 ✅”。
   - 前端页面刷新后即可显示真实素材。
5. **取消**：放弃所有“待确认”的匹配操作，恢复原状。

### 3.3 数据结构

#### Slot 配置（JSON格式，存储在服务器端）

```json
{
  "slots": [
    {
      "slotId": "IMG-01-01",
      "page": "首页",
      "description": "主视觉背景图",
      "type": "image",
      "yamlPath": "app.banner.image-key",  // 在yml中的路径
      "required": true,
      "assignedFile": null  // 当前关联的COS key
    },
    {
      "slotId": "IMG-02-01",
      "page": "云游侨乡",
      "description": "碉楼群封面",
      "type": "image",
      "yamlPath": "app.locations[0].image-key",
      "assignedFile": "images/diaolou.jpg"
    }
    // ... 更多Slot
  ]
}
```

## 四、技术实现要点

### 4.1 后端 API 新增

1.  **`GET /admin/api/slots`**
    *   **功能**：返回所有 Slot 列表（从 `application.yml` 解析）。
    *   **返回**：Slot JSON 数组。

2.  **`POST /admin/api/match`**
    *   **功能**：执行素材匹配导入。
    *   **参数**：`{ "slotId": "IMG-02-01", "cosKey": "images/diaolou.jpg" }`
    *   **处理**：
        1.  根据 `slotId` 找到对应的 `yamlPath`。
        2.  把 `cosKey` 写入 `application.yml` 的对应字段。
        3.  刷新配置（或重启部分Bean）。
    *   **返回**：成功/失败信息。

3.  **`POST /admin/api/unmatch`**
    *   **功能**：取消某个 Slot 的填充（清空 yaml 字段）。

### 4.2 前端模板改造

在所有 HTML 模板中，把原来的 `th:image` 或硬编码图片位置，统一检查 Slot 状态。如果未填充，则显示 Slot 编号占位符。

```html
<!-- Thymeleaf 模板示例 -->
<div class="card-image">
    <div th:if="${slotFilled}">
        <img th:src="${imageUrl}" alt="...">
    </div>
    <div th:unless="${slotFilled}" class="slot-placeholder">
        <span class="slot-badge" th:text="${slotId}">IMG-02-01</span>
        <span class="slot-desc" th:text="${slotDesc}">碉楼群封面</span>
        <span class="slot-status-text">待填充素材</span>
    </div>
</div>
```

### 4.3 YAML 动态更新

实现一个 `YamlConfigUpdater` 服务类，负责修改 `application.yml` 文件并刷新 Spring 的 `Environment`，使得更改即时生效（无需重启整个应用）。

## 六、方案亮点

1.  **零门槛**：美术/文案同学只需知道编号，直接在后台对应位置上传/选择素材即可，无需关心技术路径。
2.  **防错性强**：素材只能填到类型匹配的 Slot 里（比如图片不能填到视频位），填错了会有视觉提示。
3.  **实时反馈**：网站前端空位置会实时变化，一眼看出哪些还缺素材。
4.  **可追溯**：每个素材都能追溯到它填充了哪个位置，方便后期维护。
